## Actual platform transition and return

### WF-06_SYSTEM_EXTERNAL_MEDIA_CONTROLS / External media keys and controller handoff
- Trigger: A supported Bluetooth/headset/vehicle media key issues a MediaSession command.
- Handoff to REAL owner: Android routes the command; no separate app player or queue is created.
- Authoritative playback/service state: The shared service validates, serializes and acknowledges the command.
- Return recheck (never infer from onResume alone): All visible surfaces refresh from the authoritative snapshot; unsupported/unavailable returns to app manual controls.
- Safe terminal: MANUAL_PLAYBACK
- Retry/recovery bounds: No optimistic duplicate command; safe retry only after refresh.

### WF-06_SYSTEM_BLUETOOTH_ROUTE_RECOVERY / Bluetooth route loss and reconnect
- Trigger: Selected/current Bluetooth output route disconnects or reconnects.
- Handoff to REAL owner: Android route truth controls output; connection alone never opens Driving Mode.
- Authoritative playback/service state: Service immediately pauses on loss, invalidates the route and prevents speaker fallback leakage.
- Return recheck (never infer from onResume alone): Reconnect produces Safe Paused. Explicit manual Play revalidates route and waits for service acknowledgement.
- Safe terminal: SAFE_PAUSED
- Retry/recovery bounds: No automatic Resume. Failed manual Play stays Safe Paused with Exit/manual controls.
