## 2. Architecture gate — ADR-0008 explicitly reconciled

**A real problem was caught during review:** the initial P04 draft imported `data.mediastore.*` directly from `playback.service`, violating the existing strict [`check_architecture_dependencies.py`](../../scripts/check_architecture_dependencies.py) guard and Accepted ADR-0008. **It was corrected before declaring PASS**:

- `playback.api` owns the minimal resolver input contract (`PlaybackMediaResolutionPort`), opaque verified local item and process host interface.
- The **`app.di` composition root** alone imports both the playback port and the P03 concrete Android/MediaStore implementation and adapts between the two.
- The existing Android `MusicCopilotApplication` implements the Port's dependency host. `MusicPlaybackService` can request it even when Android starts playback before opening any Activity.
- Playback packages **do not import** `data.mediastore`, `data.room`, `app.di` or an Application implementation. No ADR-0008 guard weakening, bypass, separate process or new second Player. No new file access at application startup.

**Gate truth:** after this correction the actual GitHub production imports/ownership were re-reviewed statically. The full repository Python architecture script and Gradle checks still require an independent checkout/build to establish a formal executed full-tree PASS.

## 3. Invariants and edge cases

1. A new deliberate selection supplies an ordered visible Songs/Album/Artist/Folder/Search collection and clicked *occurrence index*, not an append or random/reordered subset. The service accepts P04's complete ordered list (up to 5,000). **#6 UI use case still sends a single ref; expanding that upstream collection handoff belongs to P05/P07 and remains an explicit end-to-end gap.**
2. `PlaybackQueuePolicy.validate` is run **before** MediaStore access. Bad ID/index/size/negative position returns `PLAYBACK_REJECTED` without moving the old Player queue.
3. Selected item is inspected first; non-selected individually missing/corrupt/unplayable entries are skipped; global permission revocation aborts the **whole** transition. The selected item is inspected **again last** to reduce TOCTOU exposure after scanning other candidates. Valid occurrences and relative selected index are retained. Every probe is cancellation-aware on IO, and selected URI remains transient/nonpersistent.
4. A failed preflight **never calls `player.setMediaItems`**. A committed replacement uses the sole service-owned ExoPlayer, not a shadow list. All actual player preparation/open/decode failures still require P05/P10 handling; a prior successful descriptor probe is not a durable grant.
5. Shuffle disabled, repeat disabled; `Next` does not wrap. `Previous` threshold **3000ms inclusive** restarts current and the first item cannot wrap. Seek arithmetic/upper bounds are delegated to P02 policy; unknown-duration absolute seek fails closed.
6. Queue-item tap uses `SelectQueueIndex(expectedQueueRevision,index)` with **pre/post IO revision checks** and fresh MediaStore revalidation, preventing a stale UI selection from applying to a new queue.
7. One serialized `PlaybackCommandProcessor`, 32 waiting + 1 active, typed BUSY, same-ID retry coalescing, conflicting ID rejection and capped 256 completed replay cache. System Media3 transport command convergence into this processor is **NOT YET PROVEN/FIXED** (P06).
8. System-surface restrictions against external playlist/URI insertion and notification/lock/media keys, pause-safe Audio Focus/route, corrupt decoding/skip, queue metadata and P1 restoration remain **P05–P11** tasks. Do not claim end-to-end privacy/route/media controls PASS until integration.
9. No backend, accounts, streaming catalog, personal-media uploading, source write/delete, external analytics, user song metadata or raw paths in code diagnostics. This scope statement does not certify unknown third-party/OS MediaSession controller mutation before P06.
