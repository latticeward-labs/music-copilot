## 2. Committed P05 implementation and exact boundaries

| Changed source | Concrete behavior |
|---|---|
| [`MusicPlaybackService.kt`](../../app/src/main/java/com/latticeward/musiccopilot/playback/service/MusicPlaybackService.kt) | Existing **one** ExoPlayer configured with Media3 music usage/content type and `handleAudioFocus=true`. A `Play` on `STATE_IDLE` (including Paused queue or `Stop`) calls `prepare()` before play. Explicit Play at `STATE_ENDED` seeks the retained current/last item to 0 before resuming. Existing MediaStore-checked `ReplaceQueue` honors requested play flag. Service catches sync errors without exposing messages or turning an errored prepare into a fake success. Async Buffering/Playing/Paused/Error changes still originate from Player callbacks. P09 must prove focus/route safety rather than inferring it from ExoPlayer focus configuration. |
| [`Media3SnapshotProjector.kt`](../../app/src/main/java/com/latticeward/musiccopilot/playback/media3/Media3SnapshotProjector.kt) | Full immutable service snapshot compares **actual** queue and selected occurrence. `queueRevision` changes for queue/index change, *not* for unrelated Media3 metadata/duration timeline events. `revision` is monotonically increased on each capture. Buffering and `player.isPlaying` are distinct; `playerError` is Error; Next affordance disabled at last position rather than blindly trusting a system command. Note: P06 must verify final Media3 callback ordering, index changes and controller resubscription on a device. |
| [`LibraryMediaSelectionUseCase.kt`](../../app/src/main/java/com/latticeward/musiccopilot/core/application/playback/LibraryMediaSelectionUseCase.kt) | Add optional `visibleSongRefs` and `selectedIndex` parameters, preserving historical two-parameter call sites. Fail closed on invalid selection, over-5000 refs, stale Library revision, missing selected MediaStore item or permission/controller loss. Submit `ReplaceQueue(items=entire_visible_ordered_songs,startIndex=clicked_occurrence)`, not `listOf(ref)`. Only accept service acknowledgement with exactly chosen occurrence, order-preserving subset after optional unplayable non-selected skips, and non-error Player state. A Buffering acknowledgement is **AcceptedNotPlaying**, never falsely `Playing`. |
| [`VisiblePlaybackQueuePolicy.kt`](../../app/src/main/java/com/latticeward/musiccopilot/core/application/playback/VisiblePlaybackQueuePolicy.kt) | Pure independent validation that returned queue prefix and suffix are ordered subsequences around the selected occurrence. Prevents stale/reordered/injected entries or wrong clicked duplicate occurrence being accepted. This policy cannot itself detect real audible output. |
| [`LibraryBrowseViewModel.kt`](../../app/src/main/java/com/latticeward/musiccopilot/feature/library/LibraryBrowseViewModel.kt) | On explicit song tap freeze **the loaded visible Songs rows** from Songs/Artist/Album/Folder, their exact order and selected position before launching suspension. Older scan-revision/cancellation guards remain; no auto-play on browse/scroll/navigation. |
| [`LocalSearchViewModel.kt`](../../app/src/main/java/com/latticeward/musiccopilot/feature/search/LocalSearchViewModel.kt) | On explicit local Search result tap freeze currently shown Song rows in returned search order, retain clicked index, pass through the same shared selection contract. Non-song Search entries still navigate, no auto-play on query. |

**Important pagination honesty:** Library results are paged (currently 50/page, bounded 100), and P05 queues *currently loaded UI Songs*, not every off-screen/unloaded group member. That is the **visible currently presented collection**; if product acceptance requires the complete artist/album/folder beyond loaded rows, P07/P12 must add a revision-pinned bounded complete-collection resolver rather than imply P05 has done so. The Search result cap is 60; only Song entries are queued. No hidden re-sort or save-playlist.

**Metadata honesty:** Opaque `MediaRef`/verified URI are in the service MediaItem. MediaSession notification's user-friendly title/artist/artwork are **not proven** at P05 and must be resolved locally and tested as part of P06/P07; do not label system surface metadata PASS. P09/P10 own route interruption and corrupt decoder advancement. Controller request timeout is currently 10 seconds, while full 5000-entry MediaStore verification could exceed it; P06/P12 must examine this race, cancellation and bounded performance before large-queue acceptance.
