## 3. Rules and threat boundary

1. **Same player, same policies:** MediaSession wraps one ForwardingPlayer which delegates state and events to the service-owned ExoPlayer. Standard MediaController play/pause/next/previous/seek enqueues the same commands as private UI. No concurrent second engine or optimistic playback state; ExoPlayer event callbacks publish actual status through `Media3SnapshotProjector`.
2. **Controller authorization:** only controllers reporting this application's package name **and same UID** can send private `ACTION_EXECUTE` / `ACTION_SNAPSHOT`. Every controller gets transport Player.Commands only. Unsupported changes are excluded in `onConnect`, and both Media3 and legacy playlist-creation callbacks independently fail closed (no arbitrary `http(s)`, `file://` or unverified `content://` injection).
3. **Queue ordering/security:** generic `seekTo(index, ...)` is not an advertised command, and the façade accepts it only if index equals the current item (as a seek). Arbitrary occurrence changes must use the app-private `SelectQueueIndex(expectedQueueRevision)` which P04 revalidates via MediaStore; system Previous/Next uses P02's exact 3000ms / nonwrapping edge policies.
4. **Snapshot reconnect:** controller only becomes Ready after a complete service snapshot. A later request gets a new full snapshot and only replaces it when revision strictly increases. The system session media metadata/queue always comes from the Player, not a UI copy.
5. **OS-surface metadata:** MediaStore title/artist/album are bounded, read-only, internal on IO; explicit local Media3 MediaMetadata enables system notification and lock-screen title. The **actual OS display behavior, OEM styling, BT controls and background playback are NOT TESTED**; P08/P09/P12/P13 must verify.
6. **No hidden feature scope:** no web catalog, streaming, arbitrary external playlist, account, cloud sync, separate process, Telemetry, persisted title/path/URI, or generated owner APK.
7. **Known unresolved latency/late response risk:** in-app `PlaybackControllerConnection.execute` still has its existing **10-second timeout**, while a very large 5,000-item queue probes MediaStore on IO and can outlast it. The service worker does not yet prove remote cancellation of an in-flight ReplaceQueue after client timeout. **P12 must benchmark/correct timeout/cancellation vs maximum queue and ensure no unexpected late autoplay; until then full large-queue parity and T suite are NOT_VERIFIED.** The pure transport policy is not a substitute for this testing.
8. **Other deferred responsibilities:** P07 Compose media UI/queue view metadata, P08 actual foreground lifecycle/notifications, P09 audio focus/route/headset/Bluetooth safety, P10 decoder corruption and revoked access, P11 Safe-Paused restore. External trusted/system controller behavior must be verified on OS/device; unit source inspection cannot demonstrate audible behavior.
