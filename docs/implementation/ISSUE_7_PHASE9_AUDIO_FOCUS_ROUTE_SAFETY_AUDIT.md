## 3. Approved interruption behavior

| Scenario | Service response | Automatic resume |
|---|---|---|
| Another music app gains transient focus / notification / phone call | **ExoPlayer's single owned Audio Focus manager** responds to Android with appropriate duck/pause/suppression for its USAGE_MEDIA attributes. UI observes service Player actual `isPlaying`, not a locally fabricated Playing state. | Conditional recovery is controlled by ExoPlayer/Android only while the user has **not** manually paused and no route-loss latch exists; otherwise Player is safe-paused. Phone-specific OEM timing **NOT_VERIFIED**. |
| Manual Pause or Stop during focus/call interruption | `explicitlyPaused=true`, immediate `player.pause()` or `player.stop()` | **Forbidden** until new explicit Play; callback event guard re-applies pause if focus regain attempts playback. |
| Wired headset unplug | Media3 becoming-noisy pause + `AudioDeviceCallback` removal fallback; `requiresExplicitResume=true`; Player paused before unintentional output on supported standard signals | **Forbidden** on replug alone. |
| Bluetooth A2DP/SCO/BLE/headset/hearing-aid disconnect | Same conservative service-level pause; no device names/addresses recorded, UI/MediaSession show Player's Paused state | **Forbidden** on reconnection alone; explicit user Play resumes from current output, if safe. |
| Disconnection while large queue or index validation suspends on MediaStore IO | Service route generation increments on disconnect, and older IO result is rejected without committing selected Media3 timeline or playing | **Forbidden** for that stale in-flight request; a fresh user command is needed. |
| Speaker-only normal playback / harmless UI close / Home / screen off | No external output-disconnect event; Media3 remains sole route/focus owner, P08 foreground lifecycle unchanged | Legitimate active playback continues (device behavior must be verified in P13). |

**Safety limitations / outstanding P12 review:**
1. Android may never deliver a noisy or device removal event on some OEM/vehicle outputs, or deliver it after reroute. Source cannot guarantee a **zero-millisecond speaker leak**; P13 tests M26/M27 and P12 review must validate exact phone behavior. P09 intentionally uses two *signals* without adding a second focus manager.
2. `AudioDeviceCallback` is conservative: losing a **connected but unused** wired/Bluetooth sink may pause music on a different output. This trades convenience for no unintended speaker playback, and must be checked with actual devices. It cannot claim the active sink from unprivileged generic enumeration.
3. Transient focus loss and incoming-call timing are handled by Media3, including ducking. No PHONE_STATE permission, manual telephony broadcast or second focus owner is introduced; exact Android 10/12/14+/OEM calls/duck/resume **NOT_VERIFIED**. Voice ducking belongs to the replaceable voice provider/Issue #9 and is not falsely marked complete here.
4. `routeGeneration` invalidates a request **while its suspending MediaStore resolver runs**. A previously queued Play command that only starts executing after the loss may require additional submit-time route epoch stamping; handle in P12 if reproducible, especially near the 10-second controller timeout. Avoid fake complete-pass claims.
5. No stream URL, telemetry, location, per-device identifier, pairing permission, auto player restart, dual session, persistence, new notification or process.
6. A phone-force-stop or process kill is not guaranteed to resume playback (ADR-0007); P11 later implements P1 validated Safe-Paused only. P10 owns decoder corruption/revoked-read recovery.
