## Schema and migration policy

See [v1 migration contract](ISSUE_4_PHASE6_MIGRATIONS.md) and [protobuf field definition](../../app/src/main/proto/restorable_queue.proto).
Room version 1 has one replaceable table; future released Likes/history require explicit schema migrations and preservation tests. `app/schemas/.../1.json` is generated by Room KAPT and CI requires it to exist before PASS. The protobuf version flag is validated on every read/write; future schema must not be parsed as v1 or silently restored.

### Explicit limitations

- MediaStore truth and Room library projection are connected, but no real on-device scan/permission-change instrumentation is claimed until Android device runs.
- A P1 restorable queue contains opaque refs and position by *contract* only. Actual MediaSession-aware validation, duration clamp and Safe-Paused restoration are Phase 7 responsibilities.
- Schema export by KAPT is required; Android Room migrations will be integration tested when a schema upgrade or released user-owned records exist.
- No raw voice/audio/transcript, real title/artist/path/content URI, user database, or cloud credentials are checked in.
- A failing/cancelled CI run is never evidence of Phase 6 PASS.
