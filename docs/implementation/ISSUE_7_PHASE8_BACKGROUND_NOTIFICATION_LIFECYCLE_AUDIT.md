## Lifecycle/notification details

1. **First run / browsing with no music:** Activity may bind to MediaSessionService for status only. Neither Activity nor service starts foreground, records audio, requests extra runtime permission, auto-plays or initiates MediaStore scanning. Media3 may tear down an idle unbound service naturally.
2. **Explicit user Play from Library/Search/MiniPlayer/Player or approved system transport:** P04/P05 own MediaStore revalidation, one ExoPlayer and the truthful buffer/playing state. Media3 observes actual MediaSession events and manages its own media notification and promotion to foreground. Existing P06 `MediaMetadata` title/artist/album comes from approved local-only MediaStore reads; no personal filenames/paths are logged.
3. **Home, lock, orientation change / Activity onStop:** UI controller detaches. Service-owned Player + Session remain untouched. When the user returns, the new bound controller receives one full service snapshot via P06 connection logic; no resetting the live queue/position or background autoplay is triggered by UI recreation.
4. **Swipe from Recents:** an actually foreground, user-requested Playing or Buffering media session is retained. When Paused/Ended/Error/Idle/non-foreground, delegate to default Media3 `onTaskRemoved`, which will request safe teardown instead of keeping a zombie foreground service. Do not assume survival of Android force-stop, process kill, excessive OEM background restrictions or nonstandard notification setting.
5. **Notification/lock/BT:** all remain Android-managed surfaces for the same service-owned MediaSession with P06 restricted standard transport commands; there is no independent notification queue, parallel Player, media broadcaster, second service or Compose overlay pretending to be the OS. Actual OS notification visibility/actions and route safety are unverified until final phone tests; P09 owns audio focus/route/no-speaker-leak.
6. **Android 13–15:** official MediaSession notification exception applies to POST_NOTIFICATIONS. This is not a promise that every OEM displays a drawer/lock-screen surface identically, or that system audio focus and route behavior is correct without testing.
7. **P1 cold restart:** P08 deliberately does NOT implement process-death restoration or autoplay. Only P11 is permitted to restore a validated Safe-Paused session, never automatic audible playback.
8. **Potential race for P12:** late MediaSession `onUpdateNotification` or delayed system foreground promotion immediately after an explicit Play could coincide with Recents removal before `isPlaybackOngoing` returns true; the fail-closed P08 policy may stop before promotion. P12/P13 must measure real Android startup/foreground timing. Owner/technical results are NOT_RUN, not presumed PASS.
9. **Potential UI/rotation race for P12:** concurrent old/new Activity stops and starts may briefly detach/reconnect the shared controller. Generation guard prevents stale callbacks from overwriting the snapshot. The exact result under fast rotation and OEM task dismissal needs real device inspection.
