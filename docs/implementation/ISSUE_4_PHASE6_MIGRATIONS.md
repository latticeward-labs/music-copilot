# Local data migration contract — Issue #4 / Phase 6

**Version:** initial Room projection `v1`, Proto restore `v1`.

- `app/schemas/com.latticeward.musiccopilot.data.room.MusicCopilotDatabase/1.json` is generated by Room annotation processing. Store the generated file unchanged in Git after a successful CI export and verify on later changes.
- Room v1 holds only `library_items` (rebuildable projection); recovery is a transactional rescan from MediaStore. No destructive migration fallback is registered. Any later schema containing user-owned Likes/history needs an explicit version bump, Migration and tests preserving that user-owned data.
- Preferences DataStore stores onboarding, optional Bluetooth hint, and cloud STT consent state; never platform permission truth.
- Proto v1 snapshot uses six fixed protobuf field IDs defined in `app/src/main/proto/restorable_queue.proto`, with a manually encoded `RestoreProtoCodec`. This snapshot is non-authoritative. Read rejects unsupported future schemas, corrupt payload, negative position, invalid queue index and duplicate MediaRef entries. Only future Playback Service can requery the MediaStore refs, clamp duration and restore **Paused**, never autoplay.
- The current implementation does not persist audio, transcripts, credentials, content URIs or filesystem paths.
- Data corruption cannot trigger cloud calls. No login, backend, streaming or sync.
- **Acceptance:** current schema export must be present, JVM synthetic fixture tests must run, and Android storage instrumented migration tests are still required for future released records; no device/instrumented run is claimed by this foundation phase.
